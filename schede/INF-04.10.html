INF-04.10 Recupero di file e applicazioni

Titolo d'archivio: Recupero di file e applicazioni

In breve Un backup vale solo se si riesce a ripristinarlo: il recupero parte da un client indipendente, in una cartella nuova, senza mai sovrascrivere l'unico originale.

Per chi non è del mestiere. "Job completato" vuol dire che la copia è stata scritta. "Recupero riuscito" vuol dire che qualcuno ha riaperto i dati e funzionano. Sono due eventi diversi e solo il secondo conta.

Procedura

  1. Si parte da un client indipendente, con chiavi e credenziali disponibili offline.
  2. Si apre il repository e si sceglie lo snapshot per data.
  3. Si ripristina in una directory nuova con spazio sufficiente.
  4. File: si confrontano manifest/hash e si controllano apertura, quantità e permessi.
  5. Applicazioni: database e file devono appartenere allo stesso punto nel tempo e la versione del software deve essere compatibile. Il recupero avviene in ambiente isolato, con notifiche e job esterni disattivati, fino al controllo di login, allegati, ricerca e ruoli.
  6. Si annotano nel registro sorgente, repository, snapshot, coerenza DB/file, tempi e anomalie.

Comandi di consultazione (restic)

` restic -r REPOSITORY snapshots restic -r REPOSITORY check restic -r REPOSITORY check --read-data-subset=10% restic -r REPOSITORY ls ID_SNAPSHOT restic -r REPOSITORY restore ID_SNAPSHOT --target DIRECTORY_NUOVA `

Il check semplice controlla la struttura, non legge tutto il contenuto. La percentuale è una lettura parziale: si affiancano rotazione periodica, campioni recuperati e controlli completi. Password e chiavi restano fuori dalla cronologia e dagli esempi.
